# Supplementary Material

*Diversity Is Not Enough: Why Representational Divergence Does Not Predict Fusion Utility*

Everything reported in the paper is regenerated from this archive by a single
driver script. A verification harness checks each reported number against a
fresh recomputation and exits non-zero on any mismatch.

---

## Quick start

```bash
pip install -r requirements.txt
cd code
python verify_claims.py --root ..     # exit 0 = every claim verified
```

Any check that cannot be evaluated (missing dependency or missing artifact)
fails the gate, because an unevaluated claim is not a verified claim. Use
`--lenient` to downgrade those to warnings. Note that `core.py` requires
`torch`: without it every fusion check reports MISSING and the gate will not
pass. A full run takes 30-60 minutes on CPU; the SICAPv2 fusion fits over
12,081 samples dominate.

There is no single `reproduce.py`. Each section is regenerated by its own
script in `code/` (listed below), and `verify_claims.py` asserts every reported
number against a fresh recomputation from the shipped artifacts.

`verify_claims.py` is the gate we use ourselves. If it exits non-zero, the
archive and the manuscript disagree and we want to know.

## A correction relative to the submitted version

The first submission extracted CTransPath features by loading its checkpoint
into an unmodified Swin transformer. CTransPath replaces the standard patch
embedding with a convolutional stem, so this load silently discarded 14 weight
tensors and left the patch embedding at random initialisation. `torch` raises no
error for this under `strict=False`.

The consequences were confined to that encoder but were substantial: its
accuracy was understated by 16.5–22.8 points, and its CKA with the other encoders
was understated on all three datasets, most severely on MHIST (0.006 measured,
0.679 correct).

| | submitted | corrected |
|---|---|---|
| CTransPath accuracy, BRACS | 55.25% | 74.63% |
| CTransPath accuracy, SICAPv2 | 73.42% | 89.87% |
| CTransPath accuracy, MHIST | 60.50% | 83.31% |
| CKA(UNI, CTransPath), BRACS | 0.246 | 0.569 |
| CKA(UNI, CTransPath), SICAPv2 | 0.317 | 0.739 |
| CKA(UNI, CTransPath), MHIST | 0.006 | 0.679 |

The corrected load is verified before extraction: all 200 checkpoint entries
match, including all 16 patch-embedding tensors, and `code/extract_ctranspath.py`
raises rather than extracting if any are missing. We recommend the same check to
anyone using this encoder, since the failure is silent and produces
plausible-looking features.

## Contents

```
                                 with the sampling indices, from which every
                                 CKA value in the paper is recomputable
splits/splits_<dataset>/         fixed 5-fold indices
code/                            generation, fusion, analysis, verification
results/                         outputs of the analysis scripts in code/
MANIFEST.json                    every included file and every exclusion
```

### Logits

`*_logits.npy` are out-of-fold logits: within each fold a probe is fit on the
training partition only and scores the held-out partition only, so no input
contributes to the probe that produces its own logit. Feature standardisation
statistics are estimated on the training partition alone.

CTransPath logits are produced from the *corrected* feature extraction. Because
this encoder is the subject of the correction described above, we also ship
`code/extract_ctranspath.py`, which performs the verified ConvStem load and
asserts that all 200 checkpoint entries match before extracting, so the
extraction can be repeated from the public checkpoint rather than taken on
trust.

### Feature subsets

Full feature arrays are ~260 MB and are not included. We ship a seeded 2,000-row
subset per teacher in `float16`. `code/compute_cka.py` regenerates the full
6×3 CKA matrix, linear and RBF, from these files.

Two distinct sources of error, which earlier versions of this README conflated:

- **Half precision.** On the *same* 2,000 rows, `float16` and `float32` agree
  to four decimal places. Storage precision costs essentially nothing.
- **Subsampling.** The values in the paper are full-sample computations. A
  2,000-row subset reproduces them to a standard deviation of 0.003-0.006
  (`results/cka_uncertainty.json`, Table 5), and the two effects together reach
  a worst case of **0.013** on the UNI-ResNet50 pair. `verify_claims.py` uses a
  CKA tolerance of 0.02 accordingly.

This matters for one comparison: the MHIST candidate CKA gap is 0.012, which is
inside that worst case. The paper says so in Section 4.2 and rests the
pathology evidence chiefly on BRACS.

## What is deliberately excluded

**Contaminated logits.** The feature directories in our working repository also
contain `trainval_logits.npy` / `all_logits.npy`, produced by fitting a probe on
all data and scoring the same data. These inflate apparent accuracy by up to 10
points and are excluded. Only the per-fold logits in `logits/` should be used.

**Result files from a separate project.** Our working folder is shared with an
earlier knowledge-distillation project whose result files use overlapping names
(`concat_mlp.json`, `moe_fusion.json`, and similar). Those files describe a
trained ~3.5M-parameter student and are unrelated to the frozen-logit fusion
reported here. They are excluded to avoid confusion; `MANIFEST.json` lists them.

**Superseded frozen result files.** Several `tmlr_*.json` snapshots from earlier
drafts contain values that disagree with the revised manuscript, including two
mutually inconsistent versions of the held-out test result. They are excluded;
the correct values are asserted by `code/verify_claims.py` and regenerated by
the per-section scripts listed below.

## Datasets

- **BRACS** — 3,969 regions of interest, 7 classes, assembled as
  `train + val` from the RoI release in that order; plus a 570-region test set
  from different institutions used for the shift evaluation.
- **SICAPv2** — the distribution contains 18,783 patches; we use the 12,081
  given by `partition/Test/Train.xlsx` followed by `partition/Test/Test.xlsx`,
  in that order, with four Gleason grades. The cribriform column is unused.
  Patch filenames identify the source biopsy, used for the patient-level
  evaluation.
- **MHIST** — 3,152 images in the row order of the released
  `annotations.csv`; its `Partition` column supplies the official split.

Exact orderings matter because the fold indices are positional.
`code/verify_ordering.py` reconstructs each label vector from the raw datasets
and asserts an exact match against the shipped labels.

## Determinism

`requirements.txt` pins exact versions. Three points deserve emphasis.

**scikit-learn is pinned to 1.6.1 deliberately.** Logits come from multinomial
logistic probes, and the `multi_class` parameter was removed in scikit-learn
1.7. On the binary benchmark (MHIST) the multinomial and standard binary
parameterisations differ, so a later version silently produces different
logits there. We verified that 1.6.1 with `multi_class='multinomial'`
reproduces the released MHIST logits exactly.

**Reproduction tolerance.** On the multiclass benchmarks, regenerating logits
reproduces accuracy to within one sample on BRACS (1 of 3,969) and two on
SICAPv2 (2 of 12,081) — lbfgs convergence variation across library builds, not
a difference in protocol. `verify_claims.py` uses a tolerance of 0.05
percentage points, which these fall inside and any genuine discrepancy would
not.

**CPU and teacher order are fixed.** The fusion runs on CPU because its
stopping rule compares float losses and a GPU run can select a different epoch. Teacher order is fixed because the fusion initialises class
weights with mass on the first listed teacher and is therefore weakly
order-dependent (at most 0.05 points).

### A note on `general_vision.py` vs `general_vision_fixedbase.py`

Both ship. The first selects a base per comparison, which means the
competence-matched and competence-unmatched arms do not in general share one;
the second fixes a single base per benchmark before any candidate pair is
chosen. **The paper reports the fixed-base results.** We include the earlier
script because the difference between the two is itself informative: the
measured competence-matched difference moves from −0.05 to +0.59 points when
the base is held fixed, which is a good illustration of how much a seemingly
minor design choice can matter.

## Corrections in this revision of the archive

Three values reported in earlier drafts of the paper were taken from stored
result files rather than recomputed from the released artifacts. They are
superseded by the figures below, all of which the verification harness now
checks.

| Quantity | Earlier draft | Corrected | Where |
|---|---|---|---|
| BRACS held-out fusion accuracy | 63.68% (+1.58 pp) | **57.37% (−4.74 pp)** | `results/heldout_bracs.json` |
| Pooled gain over best single teacher | +2.99 pp | **+2.97 pp** | `results/gain_decomposition.json` |
| Dose–response slope on CKA gap | +0.278 | **+0.094** | `results/robustness_of_null.json` |

The held-out correction reverses the direction of that result: the fusion does
not improve on the best single teacher under cross-institutional shift, it loses
to it. The pooled-gain correction follows from measuring against the per-dataset
best single teacher, which is Phikon-v2 on BRACS rather than UNI. The
dose–response correction follows from using the fixed-base general-vision
results rather than the superseded per-comparison-base version.

`code/verify_claims.py` covers the per-teacher accuracies, CKA values, parameter
counts, fused accuracy and ECE, the base fusions and third-teacher additions,
the BRACS oracle, the pooled null, and the held-out evaluation including its
fused accuracy, ECE and gain. It does **not** cover the Section 5 or Section 6
results, which need dataset downloads and feature caches this archive does not
contain; those ship their outputs in `results/` and their scripts in `code/`.
The Section 5 outputs are `criteria_results.csv` (n = 405) and
`dissoc_results.csv` (n = 125), from which every statistic in Section 5
recomputes directly.

An earlier version of this harness listed the held-out fused accuracy in its
`CLAIMS` dictionary but never read it, which is how an unreproducible value
(63.68%) survived several rounds of review. That block now fits the fusion on
the in-distribution logits, applies it to the held-out institutions, and
asserts the result. Note that a full run takes 30–60 minutes on CPU: the
SICAPv2 fusion fits over 12,081 samples dominate.
